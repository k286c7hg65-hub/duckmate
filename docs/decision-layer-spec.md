# DuckMate 决策层规范 v0.1

来源：`projects/duck-choice-lab/` v1+v2 离线实验（12 场景 × 15 候选，全部真 rollout；诚实口径 `DUCK_NO_TELEPORT=1`）。
适用范围：duck_orchestrator 的「说什么 → 干什么」这一段，即把自然语言目标映射到可执行行为的那一层。

## 一、候选定义规范（类型 / 参数桶 / 时长）

- 候选的原子单位 = **(技能, 参数桶, 时长)**，不是"技能"——机器人的选项是展开成时间的轨迹。
- 每个候选必须有**类型标签**，词表（当前 7 类）：
  `locomote`（步行位移）· `locomote_wheel`（轮滑位移）· `posture` · `kick` · `express` · `trick` · `manipulate`
- **粒度规则：手段差异必须体现为类型差异。** 「走过去」与「滑过去」都向前，但不是同一类候选；若类型粒度不够，选择器会把"任何能到终点的动作"都算对（实测：v1 口径下 walk 在轮滑目标里被判成功）。
- 候选集规模是**数出来的**，不是给定的。实测：枚举 15，上下文剪枝后适用 10.4。

## 二、成功判据规范（评估函数先于选择器）

- 成功 = **类型匹配 ∧ 判据达标**（两条件缺一不可）。
- 判据必须能**把异类技能的副作用判负**。反例（实测）：踢球用"球位移"判据时，走路把球推走 1.35 m 与真踢同量级 → 假成功；换"分离量"仍判不过。
- 正确做法 = 用**该类技能的物理签名**。踢球 = 冲量 `max(球速 − 鸭速) ≥ 0.5 m/s`（瞬时动量转移），实测把成功候选从
  {walk×3, kick_left, kick_right, walk_and_kick} 收敛到 **{kick_left}**。
- **顺序铁律：判据没验证前不训选择器。** 判据退化 → 离线矩阵给错标签 → 选择头学到的是噪声。

## 三、弃权出口规范（"以上都不是"是第一等公民）

- 决策层必须有显式升级出口，三个理由类（判据只用状态 + 目标，不依赖矩阵）：
  1. `precondition` —— 前提缺失（例：坐姿起步 × 目标需要站立能力 → 交长程规划插 `standup`）
  2. `closed_loop` —— 单技能窗口做不到（例：球在 0.25 m 射程外 → 需「接近→对准→踢」闭环）
  3. `capability` —— 技能库无此类型（例：转向）
- ⚠️ **判据必须用目标基类**（`posture_sit` → `posture`）。第一版用细粒度目标名比对，精确度掉到 50%（4 次全误报）。
- **触发率随目标严格度单调上升，必须写进预算**：v1 宽松口径 10% → v2 类型化口径 **33%**。v1 的 10% 是口径假低，不是真实覆盖率。

## 四、装置诚实性规范（离线实验）

- 必须声明装置里有没有**非物理自由度**。实测事故：`cmd_kick(place_ball=True)` 会把球瞬移，踢球候选白拿分；关掉后 `approach_kick` 从 ✅ 变 ❌。
- 实验脚本的 `except` 必须留 `why` + 统计异常计数。**异常被吞成 `success=False` = 假阴性，与真失败不可区分**（实测：回调里 `orch.ball_qvel_adr` 在无球场景不存在 → 首跑"除踢球外全 ✗"，看起来像结论，其实是装置坏了）。
- 纪律：**异常计数 > 0 时先修装置，再读结论**；"全是负结果"的第一假设是装置故障。

## 五、成本口径（实测，供预算）

|---|---|
| 单候选离线评估 | 124 ms（12 场景 × 15 候选 = 540 次 rollout / 66.9 s） |
