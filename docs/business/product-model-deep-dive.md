## 第一部分：产品形态的第一性原理

### 1.1 拆到公理：用户在买什么？

**先问：DuckMate 的用户到底是谁？**
- 付钱的人 = 家长（6-14 岁孩子的父母）
- 使用的人 = 孩子
- 决策链条：家长因「教育价值」买单，孩子因「好玩」留住

**公理 1：家长买的不是机器人，是「AI 时代孩子不被落下」的安心感。**
- 中国家长对 AI 的焦虑：孩子会不会被 AI 取代？该不该学编程？别人家孩子都在学什么？
- 现有答案：iPad 网课（伤眼、抽象、坐不住）、积木机器人（同质化严重、无 AI 灵魂）
- DuckMate 提供的答案 = **具身 AI 启蒙**：让孩子亲眼看到「AI 从想法变成动作」——这是屏幕课做不到的物理可验证性

**公理 2：孩子留住的不是「设备」，是「活物感」。**
- 进化心理学：儿童对「会动、会回应、像活物」的客体有内置兴趣（宠物/玩偶的吸引力）
- 双足 biped 是所有形态里最像「活物」的（走路=生命信号）
- 所以产品必须有「人格」——不是工具，是伙伴

**公理 3：硬件是入口，教育是引擎，但引擎不能是「说教」。**
- 家长为教育付费，孩子为好玩留下——两套动机必须用「玩中学」缝合
- 反例：市面「编程机器人」把编程做成任务关卡 = 孩子觉得是作业 → 弃玩
- 正确姿势：孩子先觉得「我的鸭子会走路好酷」，然后才问「怎么让它学会新动作」→ 学习动机内发

### 1.2 产品形态五层（从外到内）

```
┌─────────────────────────────────────────┐
│ ① IP 人格层：外观/性格/名字（鸭/恐龙/宠物）│ ← 孩子的情感入口（友B 模具/IP）
├─────────────────────────────────────────┤
│ ② 交互层：语音/触摸/App/表情显示          │ ← 孩子怎么跟它说话（自研）
├─────────────────────────────────────────┤
│ ③ 行为层：开源策略(走/踢/坐) + 自训技能    │ ← 它「会什么」（开源栈复用）
├─────────────────────────────────────────┤
│ ④ 学习层：课程/任务/成长体系               │ ← 家长为什么买单（Sky 课程迁移）
├─────────────────────────────────────────┤
│ ⑤ 身体层：14 自由度双足 + 传感器 + 主板    │ ← 它「是什么」（友A PCB + 友B 结构）
└─────────────────────────────────────────┘
```

**关键洞察**：五层里只有 ⑤是硬件，①②③④都是软件/内容/IP——**产品的大部分价值不在身体而在灵魂**，这正是我们可以做而 MicroDuck（只有③）没做的。

### 1.3 为什么是双足？为什么是「鸭形系」？

**双足（不是轮式/四足）**：
1. 活物感最强（孩子认知里「走路」= 活的）
2. 技术叙事最强（双足平衡 = AI 经典难题，家长觉得「值这个钱」）
3. 开源栈现成支持（MuJoCo + BAM + 9 策略 = 双足专用）
4. 差异化制高点（市面教育机器人几乎没有真双足 RL 产品）

**IP 形态（鸭/恐龙/宠物，非人形）**：
1. 人形 = 恐怖谷风险 + 「像但不够像」的尴尬 + 优必选等已有
2. 动物形 = 亲近感 + IP 化空间（换壳 = 复购引擎，友B 模具的核心武器）
3. 可换 IP 壳设计：「一台身体，多张脸」——鸭壳/恐龙壳/狗壳，模具复用，配件订阅化

### 1.4 产品家族矩阵（V1-V3，从单品到家族）

| 代际 | 产品 | 用户 | 价位 | 核心 |
|---|---|---|---|---|
| V1 | DuckMate Home（旗舰双足） | C 端家庭 | ¥1999-2599 | 教育伙伴 + 课程 1.0 |
| V2 | DuckMate Edu Kit（B 端套装） | 学校/机构 | ¥1.5-3 万/10 台 | 编程课 + 教师台 + 管理系统 |
| V2.5 | 换壳/配件/球场套装 | C 端存量 | ¥99-399 | 复购引擎（友B 模具） |
| V3 | DuckMate Creator（开发者版） | 创客/极客 | ¥2599+ | API 开放 + 技能市场 |

**B 端为什么是第二增长曲线**：中国「课后服务」政策（双减后 5+2）驱动学校采购 STEM 设备——**政府采购是教育机器人最大的量**（积木机器人品牌主要活在这）。DuckMate Edu Kit 差异化 = 真 AI（非积木）+ 教师管理系统。

## 第二部分：商业模式的第一性原理

### 2.1 拆到公理：教育硬件怎么才能不重蹈 Anki/积木机器人覆辙？

**Anki 死因**（历史教训）：硬件贵（$180+ 但成本更高）+ 内容自建（养不起内容团队）+ 无复购（一台 Cozmo 玩腻了就是玩腻了）
**积木机器人现状**：同质化 → 价格战 → 渠道商压价 → 毛利归零

**公理：硬件商业模式的生死 = 能否把一次性收入变成经常性收入（recurring revenue）。**

### 2.2 DuckMate 收入引擎设计（三层递进）

```
收入引擎
├── L1 硬件（一次性）：¥1999-2599，毛利 30-45%
│     → 获客入口，不指望它赚钱（保本微利）
├── L2 经常性（核心利润）：订阅 + 配件
│     ├── 教育订阅 ¥299/年：课程季更（编程入门→进阶→创客）
│     ├── IP 配件 ¥99-399：换壳/服饰/球场（模具复用 = 高毛利 50-60%）
│     └── 技能包 ¥29-99：单个新行为（翻跟头/跳舞，社区/官方出）
└── L3 平台（远期）：技能市场抽成 10-20%（V3 后）
```

**为什么这个结构能活（对照 Anki）**：
| | Anki | DuckMate |
|---|---|---|
| 硬件 | 贵且亏本卖 | 保本微利（供应链压成本）|
| 内容 | 自建团队（重）| 订阅制 + 课程迁移（Sky 已有）+ 社区 UGC（轻）|
| 复购 | 无（一台玩腻）| 换壳/新技能/新课程 = 持续购买理由 |
| 生态 | 封闭 | 开源 + 社区（众包内容成本）|

### 2.3 LTV/CAC 模型（3 年视角，框架）

```
CAC（获客成本）：¥400-600/台（内容种草 + 渠道分成 + 营销）
  —— 我们有现成内容资产（技术验证 demo/视频）可压低 CAC

LTV（单用户 3 年价值）：
  硬件 ¥1999（毛利 ~700）
  + 订阅 ¥299×2.5 年（毛利 ~550）
  + 配件 ¥300×2 次（毛利 ~350）
  + 技能包 ~¥150（毛利 ~120）
  ≈ LTV 毛利 ¥1700+ vs CAC ¥500 → LTV/CAC ≈ 3.4 ✅（健康线 >3）

复购逻辑：换壳（视觉新鲜）→ 新课程（能力新鲜）→ 新技能（行为新鲜）→ V2 升级（代际新鲜）
```

### 2.4 双市场结构（C 端现金流 + B 端规模化）

| | C 端（Home） | B 端（Edu Kit） |
|---|---|---|
| 客户 | 家庭 | 学校/机构/政府采购 |
| 决策 | 家长（情感+教育焦虑）| 老师/校长（课程+管理+政绩）|
| 客单 | ¥1999-2599 | ¥1.5-3 万 |
| 毛利 | 30-45% | 25-35%（量大）|
| 周期 | 即时 | 招投标（3-6 个月）|
| 内容 | 家庭课程 | 课时制课程 + 教师培训 + 管理系统 |
| 角色 | 现金流 + 品牌 | 规模化 + 壁垒 |

**B 端打法**：不直接招投标（重），走「教育渠道代理商」——已有积木机器人代理网络可借，给 30-40% 渠道毛利。

### 2.5 风险对冲（商业模式侧）

| 风险 | 对冲 |
|---|---|
| 硬件卖不动（教育硬件寒冬）| C 端预售验证（M1/M3 两关卡）+ B 端代理并行 |
| 订阅续费率低 | 内容季更承诺 + 孩子成长阶段适配（6-8 岁/9-11 岁/12-14 岁三段课程）|
| MicroDuck 官方进中国 | 本地化速度 + 教育定位 + B 端渠道先占 |
| 舵机成本崩 | 8-10 舵机入门款 + 配件先行（见 BP）|
| 政策变化（课后服务缩量）| C 端基本盘独立于政策 |

## 第三部分：反方自检（本版承重柱攻击）

**最致命一柱：「教育机器人是中国伪需求——家长买完吃灰，积木机器人已经证明这件事天花板低。」**
- 正面回应：积木机器人天花板低的原因 = 无 AI 灵魂（孩子玩三次就腻）+ 同质化价格战。DuckMate 的差异化 = 真 AI 双足（孩子持续好奇「它还能学会什么」）+ 订阅持续供给新内容。类比：iPad 游戏内购模式证明了「孩子对持续更新的数字内容付费」成立——我们把同一模式物理化。
- 但承认残留风险：**「吃灰」是教育硬件的第一杀手**。对策 = M1 需求验证必须测「30 天留存」（不是购买意愿——家长都说愿意买，要看孩子 30 天后还玩不玩）。这是本版新增的关键验证点。

**次柱：「双足在教育场景不如四足/轮式实用（容易摔、续航短）。」**
- 回应：摔 = 教育机会（孩子学会「为什么走路难」= 平衡与 AI 的第一课）；且官方策略已含摔倒恢复。续航短用充电座场景设计解决（回家 = 充电 = 仪式感）。
- 残留：真机可靠性未验证（M2 500h 耐久测试 gate）。

**第三柱：「B 端招投标需要资质/关系/回款周期长，三人团队玩不转。」**
- 回应：不走直投，走代理（借现有渠道网络），我们是产品+内容提供方。V2 才启动 B 端，V1 先验证 C 端。
